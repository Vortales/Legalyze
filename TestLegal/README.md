# TestLegal — Legalyze 1.0.5

Отдельный вариант поставки для проверки возможных ложных срабатываний антивирусов. **Отсутствие срабатываний не гарантируется.** Ни один способ упаковки или сертификат не обеспечивает универсального разрешения Defender и всех сторонних продуктов.

## Что изменено и что сохранено

- `release` не изменён. Его подтверждённые пользователем `.py` и исходная onefile-команда сохранены отдельно в **`release_reference`** (база `b019031`). Там намеренно только 11 `.py` и `BUILD_COMMAND.txt`, без ресурсов и зависимостей. Для сборки этого минимального бэкапа потребуется отдельно вернуть `data/DejaVuSans.ttf`, `icon.ico` и установить зависимости из `release`; сама копия является эталоном исходников, а не готовой самостоятельной поставкой.
- В `TestLegal/config.py`: **`CURRENT_VERSION = "1.0.5"`**. Все остальные Python-файлы побайтово совпадают с `release`. Алгоритмы браузера Win10/Win11, UI, сигналов, HWID, шифрования, API, журналирования и обновлений не менялись.
- В PE-ресурсах сборки указаны продукт Legalyze и версии файла/продукта **1.0.5.0**. Это описание продукта, не подделка издателя и не цифровая подпись.
- Вместо onefile используется **standalone**: отсутствует самораспаковка Python/Qt-окружения во временный каталог при каждом старте. Такой формат убирает один возможный источник эвристических срабатываний; он не доказывает причину конкретного детекта и не гарантирует его устранения.
- Нет дополнительного упаковщика, обфускации, патчей антивируса, исключений Defender, подмены чужого имени/подписи, отключения UAC или песочницы Chromium. Существующая прикладная защита данных сохранена.

Если сервер сообщает версию 1.0.4, имеющееся числовое сравнение версий считает 1.0.5 более новой и не должно предлагать переход назад по этому ответу. Серверные проверки доступа не обходятся; другие ограничения сервера этим изменением не отменяются.

## 1. Сборка из доверенных источников

Windows x64, Python 3.12 x64, Visual Studio Build Tools 2022 с C++ и Windows SDK. Обычный CMD, без повышения прав:

```bat
cd /d "C:\путь\к\TestLegal"
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
build_nuitka.bat
```

Используйте официальные источники Python, Nuitka, Qt и остальных зависимостей. Требования оставлены как в рабочей версии (диапазоны версий); после установки зафиксируйте фактически разрешённые версии для повторяемой сборки:

```bat
.venv\Scripts\python.exe -m pip freeze > build\requirements-resolved.txt
```

Не добавляйте этот файл, журналы сборки и служебные каталоги в пользовательскую поставку. Сохраните их у себя для расследования и воспроизводимости. При обновлении зависимостей повторите проверки.

Результат: **`build\main.dist\Legalyze.exe`** и необходимые DLL/пакеты рядом. Передавать нужно **весь `main.dist`**, не один EXE. Отчёт Nuitka находится в `build\compilation-report.xml`.

Положите тот же полный проверенный portable Chromium в `TestLegal\chromium` до сборки: BAT скопирует его в `main.dist\chromium`. Если браузера нет, BAT только соберёт приложение и напомнит о ручном добавлении. Не заменяйте Chromium случайной перепакованной сборкой. Проверяйте происхождение/хеши и подписи там, где поставщик их предоставляет. Отдельно убедитесь, что детектируется именно Legalyze.exe, а не файл Chromium или DLL. Перед повторной поставкой не смешивайте новые бинарники со старыми остатками.

## 2. Подпись собственного приложения

Для публичной Windows-поставки используйте настоящий сертификат подписи кода, выданный вашему издателю доверенным удостоверяющим центром, либо подходящий доверенный сервис подписания. Самоподписанный сертификат не создаёт публичного доверия. Подпись помогает идентифицировать издателя и контролировать целостность, но не является обещанием отсутствия предупреждений SmartScreen/антивируса. Репутационное предупреждение и конкретный malware-детект — разные случаи.

После сборки подпишите **свой** финальный EXE. Пример с сертификатом в хранилище текущего пользователя Windows и `signtool.exe` из Windows SDK (подставьте отпечаток своего сертификата):

```bat
signtool sign /sha1 YOUR_CERTIFICATE_THUMBPRINT /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 "build\main.dist\Legalyze.exe"
signtool verify /pa /all /v "build\main.dist\Legalyze.exe"
```

`/sha1` здесь выбирает сертификат по отпечатку; алгоритм подписи файла задаётся `/fd SHA256`. Сертификат должен быть доступен для подписи через поддерживаемый удостоверяющим центром токен/HSM/провайдер. Параметры хранилища и timestamp-сервиса уточняйте у своего УЦ. Команда — образец, не автоматически настроенное подписание.

Не храните закрытый ключ, пароль PFX, ключи облачного подписания или учётные данные в репозитории, BAT и переписке. Не переподписывайте сторонние Qt/Chromium-бинарники чужим именем и не удаляйте их оригинальные подписи/лицензии. После подписания не изменяйте содержимое EXE. Хеш рассчитывается **после** подписи:

```powershell
Get-AuthenticodeSignature .\build\main.dist\Legalyze.exe | Format-List Status,StatusMessage,SignerCertificate
Get-FileHash .\build\main.dist\Legalyze.exe -Algorithm SHA256
```

Сохраните SHA-256 и данные версии рядом с внутренними материалами поставки. Для архива поставки рассчитайте отдельный хеш после окончательной упаковки. Стабильно используйте одного настоящего издателя; не пересобирайте бинарник случайным образом ради изменения детекта.

## 3. Проверка с включённой защитой

1. На чистых Win10 и Win11 установите обновления ОС и антивирусных баз. Не отключайте защиту и не добавляйте программу в исключения для получения «чистого» результата.
2. Проверьте финальный подписанный комплект штатной проверкой Defender/установленного продукта, затем запустите его в изолированной тестовой среде с обычной учётной записью.
3. Проверьте вход, встраивание Chromium, набор текста, микрофон, горячие клавиши, PDF/TXT, закрытие и повторный запуск. При необходимости отдельно проверьте поддерживаемый повышенный запуск Win10.
4. Если есть предупреждение, сохраните **точное имя угрозы/тип предупреждения**, продукт и версию баз, путь обнаруженного файла, SHA-256, время и снимок сообщения. Для файла, помещённого в карантин, используйте историю защиты; не восстанавливайте его автоматически лишь ради запуска.
5. Если детект относится к зависимости или браузеру, проверьте происхождение и целостность этой части. Не считайте любой детект ложным до проверки.

## 4. Пересмотр ложного срабатывания

Если после проверки источников и поведения вы считаете срабатывание ошибочным, отправьте окончательный файл на официальный пересмотр:

- Microsoft Security Intelligence: https://www.microsoft.com/en-us/wdsi/filesubmission — выберите категорию, соответствующую вашему случаю, и укажите, что вы разработчик.
- Для других антивирусов используйте официальный раздел **false positive / submit sample** соответствующего производителя.

Приложите версию 1.0.5, SHA-256, сведения о подписанте, точное имя детекта, назначение приложения и описание компонентов (PyQt6, отдельный Chromium, локальное хранилище/шифрование). Отправляйте именно обнаруженный финальный артефакт, если условия сервиса позволяют его передать. Не отправляйте пользовательский `%APPDATA%\Legalyze`, профиль браузера, пароли, конфиг, промты и журналы с личными данными. Публичные мультисканеры могут передавать образцы третьим сторонам — учитывайте конфиденциальность кода.

После ответа производителя обновите базы и повторите проверку того же артефакта. Обращение на пересмотр не даёт гарантии сроков или удаления детекта.

## Границы результата

В этой папке подготовлены исходники 1.0.5, прозрачная standalone-сборка и процедура подписания/проверки. Сам сертификат, подпись, Windows EXE, результаты Defender и решения сторонних производителей здесь **не получены**. Без точного обнаруженного файла и названия угрозы нельзя установить причину вашего срабатывания.

Хранилище осталось `%APPDATA%\Legalyze`, журналы — `logs`, профиль — `chromium-profile`. Не запускайте `release` и `TestLegal` одновременно: у них общий профиль и конфиг. Отметка `release_revision` в журнале оставлена прежней намеренно — Python-логика не менялась, а версия приложения задаётся `CURRENT_VERSION`.
