# Legalyze 1.0.5 — встроенный Qt WebEngine

**Отдельная экспериментальная реализация.** Папки `release`, `release_reference`, `TestLegal` и `clientwin11` не изменены. Основа — рабочий TestLegal 1.0.5.

## Что изменено

Вместо запуска внешнего `chromium/chrome.exe`, поиска HWND и SetParent используется **QWebEngineView — штатный браузерный виджет Qt внутри прежнего PyQt6 GUI**. Оформление, верхняя/нижняя панели, кнопки, диалоги и глобальные горячие клавиши сохранены. Фокусом и размещением содержимого управляет Qt; браузер не стартует отдельным окном за пределами экрана.

Это **не WebView2 и не другой движок**: Qt WebEngine также основан на Chromium. Изменён механизм встраивания и управления жизненным циклом. Браузер поставляется вместе с Qt WebEngine, внешняя папка `chromium` не нужна. Версия движка может отличаться от прежнего portable Chromium.

Сохранены:
- авторизация Legalyze, HWID, шифрование и сохранение настроек;
- серверные проверки версии, баланса и списание запросов;
- выбор и загрузка промта, подготовка PDF/TXT, подтверждение появления двух вложений;
- управление микрофоном через веб-чат и существующие горячие клавиши;
- журналирование и блокировка одновременного запуска.

Для минимизации изменений существующая автоматизация сайта по-прежнему использует CDP, но подключается к **внутреннему Qt WebEngine** на случайном порту `127.0.0.1`, а не запускает чужой браузер. Локальный DevTools-порт не предназначен для доступа из сети; как и в прежнем варианте, другие процессы этого пользователя могут иметь к нему доступ. Не публикуйте этот порт.

## Исправленная последовательность загрузки

1. Виджет браузера создаётся внутри существующего окна.
2. Адрес `https://google.com/ai` открывается явным вызовом Qt `setUrl()`.
3. Браузер остаётся видимым во время входа в Google/подтверждения согласия — нет перекрывающего ожидания экспорта.
4. CDP выбирает только страницу ожидаемых Google-хостов, не произвольную `about:blank`.
5. Перед подготовкой вложений проверяются HTTPS, разрешённый хост и видимый доступный редактор. Одного `readyState=complete` недостаточно. Сам по себе редактор ещё не гарантирует успешность прикрепления: результат подтверждается прежней проверкой вложений.
6. Перед каждой попыткой передачи файла повторяется проверка готовности. Пустой `document.body` больше не используется как запасная цель drag-and-drop.
7. На подключение CDP отведено до 30 секунд, на ожидание редактора — до 120 секунд после подключения. После отказа браузер остаётся видимым: войдите в Google и обновите страницу. Повторная проверка стартует после успешной загрузки страницы.

При проблеме прикрепления действует прежний тайм-аут; после предупреждения страница остаётся доступной. После устранения причины можно повторно выбрать промт или перезапустить клиент. Навигация и загрузка сайтов не становятся гарантированными: DOM Google и доступность сервиса всё ещё внешние зависимости.

## Запуск из исходников

Windows 10/11 x64, Python 3.12 x64. Используйте отдельное виртуальное окружение и обычный запуск **без прав администратора**. Повышение не нужно для Qt-встраивания; не переносите сюда обходы sandbox или GPU-флаги старого внешнего браузера.

CMD из этой папки:

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

Добавлена зависимость `PyQt6-WebEngine>=6.8,<7`. Для нового API разрешений нужен Qt WebEngine 6.8 или новее. Pip должен разрешить совместимые версии PyQt6, Qt6, WebEngine и Qt6-WebEngine; не копируйте случайные DLL из старой сборки.

### Первая проверка без Google и авторизации

```bat
.venv\Scripts\python.exe smoke_browser.py
```

Откроется локально сформированная тестовая страница с редактором внутри Qt-виджета, затем программа проверит её JavaScript и завершится. Код возврата 0 — базовая проверка прошла; 1 — ошибка/тайм-аут. Сетевой запрос к Google не выполняется (`setHtml` использует адрес только как базовый origin). Этот тест проверяет сам Qt WebEngine, **не реальную авторизацию, загрузку файлов или ИИ**. Его отдельный профиль: `%APPDATA%\Legalyze\qtwebengine-smoke-profile`.

## Работа со страницей

Поставьте фокус внутрь приложения/браузера:
- **Ctrl+R / F5** — обновить;
- **Alt+Left** — назад;
- **Ctrl+Shift+H** — снова открыть Google AI.

Кнопки Legalyze остаются прежними. Дополнительная адресная панель не добавлена. Новые окна сайта направляются в тот же управляемый виджет. Автоматически разрешается только захват микрофона для HTTPS `google.com`, `www.google.com`, `gemini.google.com`; камера, демонстрация экрана и прочие разрешения не выдаются. Также проверьте системное разрешение Windows на доступ настольных приложений к микрофону.

**Google может ограничивать вход из встроенных браузеров.** Поддержка входа в этом конкретном Qt WebEngine должна быть проверена на реальном аккаунте и целевом сайте. Подмены User-Agent и обхода ограничений входа нет. Если сервис запрещает такой вход, эта архитектура не сможет гарантированно заменить обычный браузер: используйте прежнюю проверенную версию или планируйте официальную API-интеграцию.

## Данные

- конфиг, серверный токен, промты и логи: прежний `%APPDATA%\Legalyze`;
- **новый отдельный профиль**: `%APPDATA%\Legalyze\qtwebengine-profile`;
- старый `%APPDATA%\Legalyze\chromium-profile` не используется для Qt и не копируется в него.

Первый вход в Google понадобится заново. Не запускайте разные варианты Legalyze одновременно: конфиг и служебное хранилище общие. Этот вариант не изолирует изменения конфигурации от production — перед испытанием сохраните свою резервную копию данных. Не присылайте профиль, пароли и личный конфиг в диагностике.

В `session.start`: `release_revision = qtwebengine-embedded-v1`. События: `webengine.created`, `webengine.load_finished`, `webengine.chat_ready`, `webengine.not_ready`, `webengine.render_terminated`. Стандартное `chrome_hwnd=null` здесь **нормально**: внешнего HWND больше нет.

## Сборка Nuitka

Нужны Visual Studio Build Tools с C++ и Windows SDK:

```bat
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
build_nuitka.bat
```

Полная команда находится в BAT. Используется **standalone** с PyQt6-плагином Nuitka. Результат: `build\main.dist\Legalyze.exe`. Передавайте **весь `main.dist`**, включая `QtWebEngineProcess`, DLL, Qt resources, ICU/локализации и остальные файлы, собранные Nuitka. Нельзя раздавать один EXE или вручную удалять большие Qt-файлы. Папка portable Chromium не нужна. Старый onefile-BAT для этой версии не используйте: сначала требуется проверить standalone и корректную упаковку WebEngine.

`smoke_browser.py`, `tests`, исходники и материалы сборки не нужны пользователю готового дистрибутива. Runtime WebView2 устанавливать не требуется. Объём дистрибутива будет значительным; отсутствие антивирусных предупреждений не гарантируется.

## Проверки и ограничения

Автотесты:

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверяются неизменность бизнес-модулей и основных worker-классов, отсутствие запуска внешнего браузера/SetParent, отказ от пустой страницы и успешная готовность редактора. JavaScript-проверка при установленном Node.js выполняет реальный READY_SCRIPT на контролируемых объектах DOM; без Node она пропускается.

В среде разработки прошли 7 тестов. Импорт Qt WebEngine GUI в Linux остановился из-за отсутствия `libGL.so.1`; реальная отрисовка, Windows-сборка, вход Google, микрофон и приём файлов сервисом **ещё не подтверждены**. Не заменяйте этим вариантом проверенный релиз до испытаний на Win10 и Win11.

Закрытие теперь штатное через Qt, а не принудительный `os._exit`: CDP-соединения закрываются, фоновые задачи завершаются до уничтожения страницы/профиля. При незавершённых сетевых запросах закрытие может ждать их тайм-аутов. Это сделано для сохранности профиля Qt и предотвращения удаления работающего QThread.
