# Legalyze — release

Минимальный комплект исходников для сборки приложения Windows 10 / Windows 11 x64.

**Основа — подтверждённо рабочая версия `clientwin11` (коммит `ff2cf13`).** В релизе добавлено явное отбрасывание `clicked(bool)` на границе сигналов кнопок для совместимости с Nuitka и отметка версии исправления в журнале; остальные 9 Python-модулей побайтово совпадают с исходной версией. Алгоритмы запуска Chromium, выбора токена, встраивания окна, фокуса, горячих клавиш, экспорта и хранения данных не изменены. Исходная папка `clientwin11` сохранена.

## Состав

- `main.py` — точка входа и интерфейс.
- `browser_process.py`, `browser_focus.py`, `win32_diagnostics.py` — запуск Chromium и работа с окнами Windows. Последний модуль, несмотря на название, **не является необязательным отладочным файлом**: в нём находится рабочая Win32-логика.
- `diagnostics.py` — используемое приложением журналирование и обработчики ошибок. Сохранён без изменений вместе с существующими диагностическими событиями.
- `config.py`, `storage_paths.py`, `crypto_utils.py`, `secure_store.py`, `hwid_gen.py`, `updater.py` — настройки, хранилище, шифрование, HWID и обновления.
- `data/DejaVuSans.ttf`, `data/FONT-LICENSE.txt` — шрифт для PDF и его лицензия.
- `icon.ico` — значок EXE.
- `requirements.txt` — зависимости приложения; `requirements-build.txt` — зависимости приложения и инструменты сборки.
- `build_nuitka.bat` — полный синтаксис сборки Nuitka и необязательное копирование Chromium.

Не включены тесты, HTML-образцы, старые TXT-инструкции, диагностический BAT, скрипт PyInstaller, готовые журналы, виртуальное окружение, пользовательский конфиг и сохранённый шаблон. Файлы `Memphis.enc` / `Memphis.enc.pdfenc` также не включены: это локальные артефакты промта, а не ресурс сборки; рабочая логика получает промты с сервера и использует хранилище в AppData.

## Сборка Nuitka на Windows

Нужны **Windows x64**, **Python 3.12 x64** и **Visual Studio Build Tools 2022** с компонентами «Разработка классических приложений на C++» и Windows SDK. Собирать из обычного, не повышенного CMD. Создайте отдельное окружение, не используйте окружение с одновременно установленными `fpdf` и `fpdf2`.

Откройте CMD в этой папке:

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
build_nuitka.bat
```

BAT автоматически использует `.venv\Scripts\python.exe`, если он существует; иначе — `python` из PATH. При ошибке возвращается ненулевой код. Установка зависимостей выполняется явно командами выше, не скрыто при каждой сборке.

Основная команда внутри BAT:

```bat
python -m nuitka ^
    --mode=standalone ^
    --msvc=latest ^
    --enable-plugin=pyqt6 ^
    --windows-console-mode=disable ^
    --windows-icon-from-ico=icon.ico ^
    --include-data-files=data/DejaVuSans.ttf=data/DejaVuSans.ttf ^
    --include-data-files=data/FONT-LICENSE.txt=data/FONT-LICENSE.txt ^
    --output-dir=build ^
    --output-filename=Legalyze.exe ^
    --report=build/compilation-report.xml ^
    main.py
```

Для ручного выполнения этой команды сначала активируйте окружение (`.venv\Scripts\activate.bat`). Все локальные Python-модули включаются через импорты; копировать их рядом с готовым EXE не требуется.

Этот BAT создаёт **standalone**. Для единого EXE используйте отдельный `build_nuitka_onefile.bat`, описанный ниже. В релизном EXE отключено консольное окно, но журналирование в файлы остаётся. Манифест с требованием администратора не добавляется. Версии зависимостей в `requirements.txt` оставлены как в рабочей версии; это диапазоны, а не lock-файл, поэтому новую сборку нужно проверить после разрешения зависимостей.

## Chromium и готовая поставка

Используйте **тот же полный portable-каталог Chromium, на котором проверены Win10 и Win11**. Chromium в репозитории не поставляется и BAT его не скачивает/не обновляет.

Если перед сборкой положить каталог в `release\chromium` (с `chrome.exe` или `chromium.exe` внутри), BAT скопирует его после успешной компиляции. Иначе добавьте его вручную в результат:

```text
release\build\main.dist\
    Legalyze.exe
    ...все DLL, пакеты и плагины из результата Nuitka...
    data\
        DejaVuSans.ttf
        FONT-LICENSE.txt
    chromium\
        chrome.exe
        ...остальные файлы portable Chromium...
```

Передавайте пользователю **весь каталог `main.dist`**, а не один EXE. Его можно переименовать в `Legalyze` или упаковать в ZIP. Не удаляйте созданные Nuitka DLL, плагины Qt, данные пакетов и уведомления о лицензиях. `main.build`, отчёт компиляции, исходники, BAT и `.venv` в пользовательскую поставку не нужны. Если обновляете Chromium, сначала уберите предыдущую поставочную копию из `main.dist`, чтобы не смешивать версии библиотек.

## Хранилище и проверка

Сохранено прежнее расположение:

- `%APPDATA%\Legalyze` — конфиг, шаблон и данные;
- `%APPDATA%\Legalyze\chromium-profile` — профиль браузера;
- `%APPDATA%\Legalyze\logs\<сессия>` — журналы.

Сохранены существующая миграция старых каталогов и блокировка повторного запуска. Не запускайте диагностическую и релизную версии одновременно: они используют одно хранилище. Не вкладывайте личный конфиг, профиль, кэш или журналы в дистрибутив.

После компиляции проверьте на Win10 и Win11: вход, запуск/встраивание браузера без вспышки, набор текста, микрофон, горячие клавиши, PDF/TXT, закрытие и повторный запуск. В Win10 также проверьте используемый вами режим повышения прав. Рабочая логика исходников уже подтверждена пользователем; **новый EXE всё равно требует отдельной проверки**. В Linux-среде подготовки релиза Windows-компиляция и нативный GUI не выполнялись.


## Единый EXE: исправление clicked(bool) при компиляции Nuitka

В присланных журналах обеих ОС программа доходит до окна входа, но `_do_login` получает два позиционных аргумента вместо одного: `self` и `checked` от кнопки. `@pyqtSlot()` в проверенном исходном запуске работал, однако в этой скомпилированной поставке не обеспечил отбрасывание аргумента перед обёрткой `@stage`.

Исправлены **все 15 подключений clicked** в `release/main.py`: аргумент отбрасывается явно, например:

```python
self.login_btn.clicked.connect(lambda _checked=False: self._do_login())
```

Это не обход ошибок через catch/retry: обработчик вызывается ровно один раз, а TypeError внутри обработчика по-прежнему регистрируется. Тела обработчиков, авторизация, HWID/шифрование, запуск Chromium, встраивание, фокус, таймеры, горячие клавиши и миграция хранилища не изменены.

Обновите `release/main.py` и `release/diagnostics.py`, затем **пересоберите** EXE. Замена .py рядом со старым onefile EXE его содержимое не обновляет. В CMD из `release` после установки зависимостей:

```bat
build_nuitka_onefile.bat
```

Полная команда записана в BAT: она использует `--onefile`, PyQt6 plugin, шрифт и его лицензию, значок и отключённую консоль. Результат отделён от standalone: **`build-onefile\Legalyze.exe`**. Рядом должен находиться **полный** `build-onefile\chromium`; если `release\chromium` существует, BAT копирует его автоматически. Chromium не встраивается в EXE и не обновляется. Для onefile пользовательская поставка — EXE и папка Chromium, не внутренние `main.dist`/`main.build`. Ресурсы Python/Qt и шрифт распаковываются самим Nuitka.

В новом `session.start` должны появиться `release_revision: "qt-click-adapters-v1"` и `nuitka_compiled: true` для Nuitka-сборки. `frozen: false` само по себе не означает запуск исходников: это отдельный флаг `sys.frozen`, на который Nuitka не обязан опираться. Записи `not in metadata` не доказывают отсутствие установленных/включённых модулей и не являются причиной TypeError кнопки.

Отсутствующий WMIC в Win11 включает прежний PowerShell fallback. `InvalidToken` в журнале относится к чтению локального сохранённого секрета, а не к отправленному запросу авторизации; повторно введите учётные данные. Ни алгоритм HWID, ни ключи шифрования для исправления кнопок не менялись.

Проверки: 45 offline-тестов, в том числе настоящий QtCore-сигнал `bool` с исходным телом `_do_login`, значения False/True, все 15 адаптеров и отсутствие повторного вызова при внутреннем TypeError. QtWidgets smoke пропущен без libGL. Попытка компиляции отдельного smoke-теста Nuitka в Linux прошла Python-оптимизацию/генерацию C, но остановилась без Python.h; выполненный скомпилированный тест и готовый Windows onefile EXE здесь не получены. После сборки проверьте вход, остальные кнопки, браузер и экспорт на обеих ОС.
