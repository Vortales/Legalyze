# Legalyze 1.0.5 — Universal: встроенный браузер + голос + горячие клавиши

**Рекомендуемая версия.** Отдельная папка: `release`, `release_reference`, `TestLegal`, `TestLegalQtWebEngine` и `clientwin11` не изменены. Основа — вариант `TestLegalQtWebEngine`, который вы проверили (авторизация, GUI, браузер, файлы, запросы и ответы работают), плюс устранение всех выявленных недостатков:

1. не работали глобальные горячие клавиши (скрытие окна, начало/конец голосового ввода);
2. не было кнопки микрофона в странице чата;
3. пропал нативный zoom 67%;
4. при запуске мигали неочищенные элементы сайта;
5. остался логотип Google;
6. на чистом `%APPDATA%` первый запрос мог «виснуть».

Логика авторизации, взаимодействие с сервером Legalyze, внешний вид GUI, подготовка промтов, экспорт PDF/TXT, запросы/ответы и списание баланса **не изменены** — подтверждено тестами (байт-в-байт сравнение бизнес-модулей и worker-классов с проверенным вариантом).

## 1. Анализ причин дефектов

### Микрофон пропал из-за двух причин
1. **Zoom.** В прежней версии в профиле Chromium стоял нативный browser zoom 67% (Chrome `Ctrl+-` до 67%, уровень `-2.2239`). При ширине окна 453 px без zoom фактическая ширина «вьюпорта» страницы ~453 px, и сайт рисует **узкую раскладку без кнопки микрофона** (остаются только поле ввода и кнопка отправки — ровно то, что вы видели). С zoom 67% вьюпорт ~676 px — полная раскладка с микрофоном. **Zoom восстановлен** (нативный `setZoomFactor(2/3)` — тот же шаг «67%» в Chrome, применяется до первой загрузки).
2. **Web Speech API.** Кнопка голоса на сайте дополнительно проверяет наличие `SpeechRecognition`. В настоящем Chrome распознавание — облачный сервис Google с проприетарными ключами; в Qt WebEngine (Chromium без них) рабочего сервиса нет. Поэтому установлен совместимый `SpeechRecognition`-шим (раздел 2).

### Горячие клавиши не работали из-за конкретной ошибки
Служебное окно Win32 для `RegisterHotKey` создавалось оконной процедурой, которая возвращала 0 для **всех** сообщений, включая `WM_NCCREATE`. По правилам Win32 возврат 0 из `WM_NCCREATE` **отменяет создание окна** — `CreateWindowExW` завершалась неудачей, регистрация клавиш не происходила. Исправлено: оконная процедура корректно вызывает `DefWindowProcW`; даже если окно не создастся, горячие клавиши работают через резервный опрос клавиатуры (`GetAsyncKeyState`), а конфликтующие с другим приложением клавиши автоматически переподключаются каждые 10 секунд. Независимость от Qt-окон и фокуса сохранена.

### «Вечная прогрузка» на чистом %APPDATA%
На свежем профиле Google показывает карточку согласия (cookie/«Before you continue», `div.qEn1od`). Прежняя очистка интерфейса **прятала** карточку, но не принимала её — страница оставалась в состоянии «согласие не дано», и запрос зависал; после нескольких запусков/перезапусков cookie всё же появлялся, и всё начинало работать. Теперь согласия с точными кнопками («Принять все» / «Accept all» / «I agree») **принимаются автоматически** — только внутри cookie-диалогов и на `consent.google.com`, никакие другие кнопки не нажимаются.

### Мигание элементов при запуске
Очистка интерфейса выполнялась только после подключения CDP — первые секунды страница была видна целиком. Теперь очистка (как и согласия, zoom, шим речи) вводится **на этапе создания документа**, до первого кадра: пользователь не видит ни логотипа, ни шапки, ни «не той» раскладки.

## 2. Голос (как работает)

В страницу до её загрузки вводится совместимый `SpeechRecognition`/`webkitSpeechRecognition` (если родного нет). Диктовка работает по-настоящему:

```
сайт вызывает SpeechRecognition → мост QWebChannel (не блокируется CSP сайта)
  → скрытый хост Windows PowerShell + System.Speech (штатный движок Windows)
  → распознанный текст возвращается в поле ввода сайта
```

- **Работает на всех Windows 10/11**: PowerShell 5.1 и .NET System.Speech входят в состав Windows; сторонние Python-пакеты и облако не нужны. Речь не покидает компьютер.
- Промежуточные и финальные результаты, `continuous`, `interimResults`, стандартные события (`onresult`, `onerror`, `onend`…).
- Понятные ошибки: нет языкового пакета речи → `language-not-supported`; закрыт доступ к микрофону → `not-allowed`.
- Мост речи использует `qwebchannel.js` из ресурсов Qt, а при его отсутствии — встроенный совместимый клиент (проверен тестами по протоколу Qt).

**Требования:** настройки Windows → «Конфиденциальность → Микрофон» → доступ для настольных приложений включён; установлен языковой пакет речи (для русского — «Речь» в компонентах языка). Точность локального распознавания Windows уступает облачному Google — речь при этом остаётся на компьютере; текст можно править перед отправкой.

Порядок работы прежний (ТЗ):
- **1-е нажатие** F3 → сайт начинает запись (кнопка микрофона найдена и «нажата»);
- **2-е нажатие F3** → отправка голосового запроса.

Если кнопка не найдена (сайт изменил DOM) — в статусе «Кнопка микрофона не найдена», в логах `mic.button_missing`.

## 3. Почему эта архитектура

| Вариант | Итог |
|---|---|
| Portable Chrome + HWND/SetParent | Работает по-разному у разных пользователей (права, GPU, фокус, AV). Отклонён. |
| WebView2 (Edge) | Тот же Chromium, но Runtime ставится на каждой машине отдельно + снова чужой HWND/COM. |
| Playwright/Selenium | Внешний браузер + драйвер. |
| **Qt WebEngine (выбран)** | Движок поставляется с приложением одинаковым на всех ПК; окно — родной Qt-виджет; zoom 67%, голос, согласия, очистка UI — под контролем приложения. |

Ограничение честно: движок — всё равно Chromium (встроенный и единый). Совместимость с конкретным сайтом ИИ и входом Google остаётся внешней зависимостью; DOM сайта может меняться. «На все сайты и аккаунты» не гарантирует никто — есть воспроизводимое поведение, диагностика и чек-лист приёмки.

## 4. Установка и запуск (Windows 10/11 x64)

Python 3.12 x64, обычный запуск **без прав администратора**. CMD из этой папки:

```bat
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

Зависимости: `PyQt6-WebEngine` (браузер). Модуль `PyQt6.QtWebChannel` (мост речи) **входит в базовый пакет `PyQt6`** — отдельный пакет не нужен и не существует на PyPI (первый прогон это показал). Папка `chromium` не нужна.

### Быстрая проверка без входа в Google

```bat
.venv\Scripts\python.exe smoke_browser.py
```

Проверяются: zoom 67%, готовность страницы, поиск и «нажатие» кнопки микрофона, наличие Web Speech API и захвата аудио. Код возврата 0 — всё прошло.

### Автотесты

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

26 тестов: неизменность бизнес-логики, отсутствие внешнего браузера/SetParent, защита микрофона/логотипа при очистке, JS-шим речи, авто-принятие согласий, протокол QWebChannel, горячие клавиши, worker готовности (Node.js). Все 26 проходят.

## 6. Что улучшено дополнительно

- **Нативный zoom 67%** (Chrome-шаг 2/3) — применяется до первой загрузки, без вспышки другой раскладки; широкая раскладка с кнопкой микрофона восстановлена.
- **Очистка UI с самого первого кадра**: шапка Google, меню аккаунта, навигация, снэкбары и логотип Google скрыты сразу — без миганий. Панель ввода, микрофон, отправка, файлы и их иконки **никогда** не скрываются (проверено тестами).
- **Совместимость User-Agent**: метка `QtWebEngine` убрана, client hints приведены к Chrome.
- **Согласия Google принимаются автоматически** (cookie-диалоги и consent.google.com) — чистый первый запуск работает без ручных перезапусков.
- Разрешение микрофона выдаётся автоматически для HTTPS-адреса страницы ИИ; камера/экран запрещены.
- Ошибки видимы: кнопка не найдена, конфликт горячих клавиш, проблемы загрузки.

## 8. Чек-лист приёмки на Windows 10 и 11

1. `smoke_browser.py` → `SMOKE OK` (включая `zoom_native_67`).
2. Запуск без администратора: вход в Google, главное окно, чат; **без мигания** шапки/логотипа; zoom страницы ~67%.
3. Кнопка микрофона **видна**; F3 — запись, повторный F3 — отправка; текст диктовки появляется в поле ввода.
4. F2 скрывает и возвращает окно (в том числе при фокусе внутри браузера).
5. Выбор промта → экспорт PDF/TXT → два вложения → запрос → ответ → «КОНЕЦ ОТВЕТА».
6. Удалить `%APPDATA%\Legalyze`, запустить заново, войти, отправить запрос — ответ приходит **с первого раза**.
7. Списание запроса и блокировка при нуле; смена горячих клавиш; закрытие без зависаний.

## 9. Известные ограничения

- Реальная приёмка на ваших ПК обязательна (прогон выше); в среде разработки нет Windows/GUI.
- Вход Google может ограничиваться для встроенных браузеров; обходов блокировок нет и не будет.
- Точность локального распознавания зависит от языкового пакета речи Windows.
- Домен сайта ИИ может менять DOM — правятся JS-селекторы, бизнес-логика не затрагивается.
- Антивирусные предупреждения не гарантируются; решения по подписи — как в `TestLegal/README.md`.

В `session.start`: `release_revision = universal-embedded-v1`.
